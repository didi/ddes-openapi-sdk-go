## 通用说明

- **通用鉴权参数**：所有接口均需 `client_id` / `access_token` / `company_id` / `timestamp` / `sign` 五个参数，已完整列入各接口请求参数表，不再单独说明。
- **集团账户（上级公司统一对接）**：4 个分页查询接口的 v2 备用路径（#2、#7、#16、#31）已单独列为独立条目，其完整请求参数表在主接口参数基础上并入 `belong_enterprise_name` / `taxpayer_no` / `query_sub_company` / `next_token` 四个集团参数；分页参数保留 `length`（每页条数，最大 100，依据服务端 IDL）与 `next_token`（游标）——请求不使用主接口的 `offset` / `last_id`，响应不含 `data.total`，保留 `data.next_token`（空字符串或 null 表示无下一页）。其余无备用路径的接口，文档以"集团账户参数变化"小节给出同一 URI 下的集团账户新增参数 `belong_enterprise_name` / `taxpayer_no`（二者任选其一），保留在各接口小节内。
- **业务参数（param_json）**：POST JSON 接口的业务参数嵌套在 `param_json` 字段内，以 JSON 字符串形式传入；`Member/single`、`Member/edit` 的业务参数嵌套字段名为 `data`，按各接口小节实际标注为准。
- **请求方式差异**：GET 接口使用 `application/x-www-form-urlencoded`，POST 接口使用 `application/json`。
- **嵌套结构**：响应 `data` 内的嵌套结构（records[]、card_list[]、limit_rule_list[] 等）在各接口"响应 data 结构"小节逐层展开至叶子字段，字段名使用完整相对路径（如 `data.records[].card_list[].card_type`）。

# 法律实体（LegalEntity）域接口参数

### 1. /river/LegalEntity/get（查询公司主体）

- **HTTP URL**：`/river/LegalEntity/get`
- **HTTP Method**：GET
- **Content-Type**：application/x-www-form-urlencoded
- **接口说明**：查询企业在滴滴企业版管理后台的公司主体档案信息，用于校验、核对滴滴后台的数据。接口仅返回正常有效的公司主体信息，自动过滤禁用、过期的无效公司主体数据。
- **文档**：https://opendocs.xiaojukeji.com/version2024/11123

#### 请求参数

| 字段名 | 字段说明 | 类型 | 必填 | 备注 |
|---|---|---|---|---|
| client_id | 应用唯一标识 | string | Y | 滴滴开放平台创建应用时，由平台分配的唯一标识，用于识别调用方身份 |
| access_token | 接口调用授权凭证 | string | Y | 授权认证后获取的访问令牌，用于校验接口调用权限；授权认证方式参见【接口认证-授权认证】 |
| company_id | 租户唯一标识 | string | Y | 滴滴企业版租户唯一 ID，代表当前操作的企业主体 |
| timestamp | 当前时间戳 | int | Y | 当前时间戳，精确到秒级 |
| sign | 签名 | string | Y | 根据规则生成的接口签名，用于校验请求合法性与完整性；生成方式参见【接口认证-授权认证】 |
| keyword | 关键字 | string | N | 模糊查询条件，可以使用 out_legal_entity_id（公司主体外部编号）或 name（公司主体名称）查询 |
| legal_entity_id | 滴滴侧公司主体id | string | N | 可使用滴滴侧公司id精准查询 |
| out_legal_entity_id | 公司主体外部编号 | string | N | 可使用公司主体外部编号精准查询 |
| offset | 数据开始位置 | int | Y | 数据分页起始位置，从 0 开始计数，后续查询需为 length 的倍数 |
| length | 数据条数（最大100条） | int | Y | 每页返回数据条数，最大值为 100，超过则按 100 条返回 |

| data.records | 公司列表 | array | 分页返回的公司主体信息数组，无数据时返回空数组 |

### 4. /river/Member/getQuota（员工限额查询）

- **HTTP URL**：`/river/Member/getQuota`
- **HTTP Method**：GET
- **Content-Type**：application/x-www-form-urlencoded
- **接口说明**：根据员工唯一标识，按指定类型查询日期范围内的限额与剩余额度信息。日期跨度规则：查询的开始日期与结束日期间隔不得超过 6 个月。查询类型：monthly_limit_only_query=1（仅按自然月查询）——未传日期查询当月；只有开始日期查询开始日期所在月；只有结束日期查询结束日期所在月；有开始/结束日期且是自然月则查询开始月至结束月的每个月；非自然月系统自动修正为该月首尾（如传 2020-05-03 至 2020-06-22，自动查 2020-05-01 至 2020-06-30）。monthly_limit_only_query=2（查询所有限额）——未传日期报错；有开始/结束日期返回所有限额类型的数据。

### 6. /river/Member/edit（员工单个修改）

- **HTTP URL**：`/river/Member/edit`
- **HTTP Method**：POST
- **Content-Type**：application/json
- **接口说明**：员工修改新增接口，用于单条员工数据修改。频率限制：连续添加员工时，请求间隔必须 ≥ 200 毫秒；如需批量新增/修改员工，请使用员工批量处理接口。AES Key 生成规则：AES Key 采用固定前缀拼接公司 ID 后进行 MD5 加密生成，公式：MD5(sprintf("es_traveler_%s", companyId))，即 es_traveler_ + 滴滴企业版租户唯一 ID，拼接后进行 MD5 加密，结果即为 AES Key。

### 7. /river/Member/del（员工删除）

- **HTTP Method**：POST
- **Content-Type**：application/json
- **接口说明**：用于删除已维护的员工信息。删除操作不可逆，删除后若再添加信息一致的员工，会作为新账号处理，原历史信息无法恢复；删除数量上限：单次请求最多删除 100 个员工。当前租户的初始管理员不能删除（需先转让管理员权限）；员工如果有未结束或未支付的订单无法通过接口删除（此时会将员工设为离职，离职员工不能继续企业支付）；因此导致的已离职、处于待确认状态（未加入企业）的员工无法通过接口删除。
